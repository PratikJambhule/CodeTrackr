## 1. Data-flow trace (as actually implemented)

```
VS Code events
  └─ onDidChangeTextDocument / onDidSaveTextDocument / onDidChangeActiveTextEditor
     ├─ markActivity()            → state.lastActivityMs, clears isPaused, focusTracker.noteActivity()
     └─ EditorTracker.recordChange()  (gross counters)
  ├─ FocusTracker  — own 15s ticker, accrues focusedMs/blurredMs by WINDOW FOCUS (not activity)
  ├─ EditorTracker — own 5s sampler, splits focused time into readMs/writeMs
  ├─ TerminalTracker / GitStateTracker / DebugTracker — event-driven
       │
  main setInterval(flushIntervalSeconds=30s)
       ├─ idle ≥ 2min  → build idlePayload, maybe send, isPaused = true, startedMs = undefined
       └─ else flushIfNeeded()
             ├─ totalBuffered < minFlushMinutes(2) → return
             ├─ buildPayload()  ← ⚠️ CONSUMES (resets) ALL TRACKERS HERE
             ├─ !payloadHasSignal → return                    ← ⚠️ consumed data discarded
             └─ sendActivity() → axios POST /api/extension/track
                   ├─ duration < 1s or > 3600s → return       ← ⚠️ consumed data discarded
                   ├─ no apiKey → return                       ← ⚠️ consumed data discarded
                   └─ catch(err) — swallows, never rethrows    ← ⚠️ makes caller's catch dead
       │
  backend routes/extension.js
       ├─ verifyApiKey → User.findOne({apiKey})
       ├─ validateIngestPayload (duration 0<d≤3600, length caps, timestamp window)
       ├─ normalizeEditor/Focus/GitAnalytics — sparse (missing ⇒ absent, not 0)
       └─ planActivityWrite → Activity.findOneAndUpdate($inc) into
          (userId, projectName, language, bucketStart) 10-minute bucket
       │
  MongoDB `activities`
       ├─ nightly dailyRollup (cron 30 3 * * *, beforeDays=2) → `dailysummaries`
       │     └─ ⚠️ NOT CONSUMED BY ANY READ PATH
       └─ GET /api/metrics → metricsService.buildMetrics (4 aggregates, uncached)
             └─ metricsDerive (pure) → 11 fields → Insights.tsx
```

## 2. What every raw value actually means (traced, not assumed)

| Field | Produced by | **Actual meaning** | Gotcha |
|---|---|---|---|
| `duration` | `flushIfNeeded`, `Math.round(totalBuffered*60)` | Wall-clock seconds since `startedMs`, **including idle < 2 min** | Inflated by short idles (L-7). Not "active coding time". |
| `focusAnalytics.focusedMs` | `FocusTracker.accrue()` on a 15 s ticker | **Time the VS Code window was in the foreground.** No activity required. | 🔴 Keeps accruing while the main loop is idle-paused (see B6). Not a work clock. |
| `focusAnalytics.flowBlocksMs[]` | `lastActivityMs − blockStartMs`, closed after 2 min idle | **Activity-bounded** work stretches. The best "real work" signal in the system. | An open block spans flushes and is emitted **once, in full, in the flush where it closes** — so a bucket can hold a block far longer than 10 min. |
| `focusAnalytics.longestBlockMs` | max of blocks **closed in this flush** | Per-flush max (correctly `$max`-ed on rollup) | — |
| `editorAnalytics.linesInserted` | `(text.match(/\n/g) \|\| []).length` | **Count of newline characters inserted** — i.e. line *breaks* created | Typing a long line without Enter = 0. Not "lines of code added". |
| `editorAnalytics.linesDeleted` | `range.end.line − range.start.line` | **Line boundaries spanned** by the deletion | Intra-line deletion = 0. |
| `editorAnalytics.churnLines` | deleted lines matched against inserts ≤ 10 min old | Lines written then deleted quickly | Bounded by `linesInserted`, so `churnLines/linesInserted ∈ [0,1]` ✅ |
| `editorAnalytics.readMs` / `writeMs` | 5 s sampler: edit in last 5 s ⇒ `writeMs += 5000`, else `readMs += 5000` | Focused time quantised into read/write | 🔴 Also accrues while idle-paused. `readMs+writeMs` ≈ focused time, a *different clock* from `focusedMs`. |
| `editorAnalytics.fileSwitches` | `onDidChangeActiveTextEditor` count | Editor-tab activations | Fires on opens, diffs, previews — a noisy proxy for context switching. |
| `editorAnalytics.uniqueFiles` | `Set.size` | **Not additive** — correctly excluded from `EDITOR_INC`; `files[]` replaces it on read ✅ | — |
| `gitAnalytics.commits` | `repo.state.HEAD.commit` changed | Commits observed via the built-in Git API (incl. GUI commits) ✅ | Rebase/amend also moves HEAD → counts as a commit. |
| `terminalAnalytics.*` | shell-execution start/end + exit code | Command/build/test counts and failures ✅ | `successRate`/`buildSuccessRate` are **derived percentages**, not additive — see §4 B8. |

## 3. 🔴 Extension bugs (root cause of most bad metrics)

### B1 — Signal-less flush **destroys** already-consumed counters
`flushIfNeeded` calls `buildPayload()` (which calls `consumeInterval()` on every tracker,
**resetting them**) and only *then* checks `payloadHasSignal(payload)`; on false it `return`s.
`hasSignal` checks only `charsInserted/charsDeleted/saveCount/linesInserted/linesDeleted/
totalCommands/commits/flowBlocksMs.length`. It does **not** check `readMs`, `writeMs`,
`fileSwitches`, `focusedMs`, `blurEvents`, `undoCount`, `buildRuns`, `testRuns`,
`debuggingSessions`, `terminalErrorCount`, `filesChanged`.

**Effect:** an interval spent *reading code and switching files* (no edits) is silently
destroyed. `comprehensionLoad` therefore **under**-reports reading — the opposite of the
intuitive guess.

### B2/B4 — `sendActivity` early-returns also destroy consumed counters
`sendActivity` returns early on `duration < 1s`, `duration > 3600s`, and missing API key —
all *after* `buildPayload` already reset the trackers. Same data loss. The "no API key" case
means **a user who hasn't pasted their key yet loses data continuously** rather than buffering.

### B3 — The retry-on-failure path is **dead code**
```js
try { await sendActivity(payload); state.bufferedMinutes = 0; }
catch { state.bufferedMinutes = totalBuffered; }   // unreachable
```
`sendActivity` catches its own axios error and never rethrows, so the `catch` never runs and
`bufferedMinutes = 0` always executes. **Every failed upload silently loses that interval.**
`CODETRACKR_PROJECT_CONTEXT.md`, the interview docs and the README all claim "buffered in
memory, retried next tick" — **that behaviour does not exist.**

### B6 — `focusedMs` / `readMs` accrue during idle-pause → denominators explode
`FocusTracker`'s 15 s ticker and `EditorTracker`'s 5 s sampler run on their **own intervals**,
independent of the main loop. While `state.isPaused === true` nothing consumes them, and
`markActivity()` clears the pause **without** resetting the trackers.

**Worked example:** code 09:00–09:30, walk away (window left focused), return 14:00.
The first flush after 14:00 carries `focusedMs ≈ 5 h`. Then
`deepWorkRatio = deepMs / focusedMs` → ≈ 0.
**This is the root cause of `deepWorkRatio` being meaningless in production.**

### B5 — Sub-threshold work is discarded at pause
The idle branch flushes only when `activeDurationMin > minFlushMinutes`, then unconditionally
sets `bufferedMinutes = 0`. Work shorter than the threshold before an idle gap is dropped.

## 4. 🟠 Backend metric defects

- **B7 `deepWorkRatio`** — `deepMs / focusedMs` mixes two clocks (activity-bounded blocks ÷
  window-focus time) *and* the denominator is corrupted by B6. Denominator should be total
  flow-block time.
- **B8 derived percentages are `$inc`-accumulated** — `terminalAnalytics.successRate` and
  `buildSuccessRate` are *percentages* computed client-side. Verify whether they are in
  `TERMINAL_INC`; summing percentages across flushes is meaningless. *(→ verified in §6)*
- **B9 `truePeakWindow`** — no sample floor. One commit in an hour you coded once in 30 days
  scores 10 and wins. Weights (`×10`, `/10`, `/5`) are unvalidated. Roadmap #16 specifies a
  **2-hour** window; the code uses 1 hour.
- **B10 `consistencyIndex`** — `1 − CV` over **only days that had activity** (the `$group`
  emits no zero-days). It therefore measures *volume evenness on active days*, **not** cadence,
  despite the name and the UI label.
- **B11 `estimationCalibration` is structurally dead** — no route sets `Goal.status = 'completed'`
  (only `seed-demo-insights.js`). Additionally `buildGoalPairs` joins on
  `language ∈ {goal.techStack}` (free text — "React" never matches `typescript`) with **no date
  window**, so it sums *all activity ever* in that language.
- **B12 no confidence/sample-size anywhere** — 3 days of data renders identically to 6 months.

## 7. 🔴 End-to-end verification (Phase 14) — the most important finding

Measured against the **live** database, read-only (`backend/scripts/probe-activity-shape.js`,
`backend/scripts/measure-insights.js`).

### 7.1 None of the backend work is deployed

```
total activity documents  : 7034
bucketed (post 2026-09-08):    0     ← every single document is legacy per-flush
legacy per-flush          : 7034
newest document           : 2026-09-09T17:57:41Z
```

**Zero documents have `bucketStart`.** The 10-minute bucketing shipped on 2026-09-08 and writes
`bucketStart` on every insert, so if the deployed backend were running that code, documents
written on 2026‑09‑09 would carry it. They do not. **The `feat/security-and-insights` branch has
never been deployed** — Render is serving pre-2026-09-08 code. Everything in the last three
batches is correct and tested but not live.

*Attempted corroboration:* direct probes of `https://codetrackr-backend-uckp.onrender.com`
(`GET /`, `GET /health`) timed out at both 25 s and 90 s. That is consistent with a spun-down or
suspended Render free instance, but a timeout is not proof on its own — it could equally be a
local network restriction. **The deployment conclusion rests on the database evidence above,
which is unambiguous**, not on the unreachable endpoint.

### 7.2 The production extension is not sending analytics

The newest stored document is, in its entirety:

```json
{ "duration": 120, "language": "latex" }
```

No `editorAnalytics`, no `focusAnalytics`, no `gitAnalytics`.

```
                                        docs with a non-zero value
editorAnalytics.linesInserted                   140  of 7034   (2%)
focusAnalytics.focusedMs                        140  of 7034   (2%)
focusAnalytics.flowBlocksMs (non-empty)         140  of 7034   (2%)
gitAnalytics.commits                             39  of 7034
terminalAnalytics.totalCommands                 131  of 7034

first .. last carrying focusAnalytics    2026-07-15 .. 2026-08-27
first .. last carrying terminalAnalytics 2026-05-13 .. 2026-09-09
```

Rich analytics exist only for **2026‑07‑15 → 2026‑08‑27** — the window when a development build
was running. Since 2026‑08‑27 the live stream carries duration and language only.

**Consequence:** every focus-derived metric (`deepWorkRatio`, `flowBlocks`, `comprehensionLoad`,
`contextSwitchesPerHour`, `interruptionsPerHour`) has no input from live data. The confidence
gating added in this batch is what makes that *visible* instead of rendering a confident 0 —
the probe output shows exactly that:

```
deepWorkRatio          insufficient  (0 flow blocks)
churnRatio             insufficient  (0 lines inserted)
comprehensionLoad      insufficient  (0 attention ms)
volumeStability        low           (6 active days)
truePeakWindow         low           (3 days in window)
```

This is the system behaving **correctly**: it is refusing to invent numbers it cannot support.

### 7.3 Query performance is fine — measured, not assumed

```
window query (30 days) : IXSCAN, 32 docs examined / 32 returned, 1 ms
buildMetrics cold      : 239 ms   (90-day baseline recomputed)
buildMetrics warm      : 44 ms    (baseline cached)
```

The `{userId:1, timestamp:-1}` index gives perfect selectivity — keys examined equals documents
returned, so there is no over-scan to optimise. The baseline cache is worth 5.4×, which
justifies it; nothing else needs caching at this scale. **No further optimisation is warranted
on the evidence.**
